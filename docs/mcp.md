# 夹夹 MCP 契约

**状态：** 服务端何时在生产开放以 [jiajia.fun](https://jiajia.fun) 为准；兼容清单已按客户端联调结果填写（见「兼容清单」）。工具定义以本仓库为准：`src/contract/` 生成 `schema/tools.json` 和 `schema/prompts.json`，字段的精确类型以它们为准。现在是草案，在生产开放前冻结，之后只做「版本规则」里的兼容变更。

## 速览

- 端点：`POST https://jiajia.fun/mcp`，Streamable HTTP，无状态。
- 登录：所有请求都要登录，没有匿名访问。凭证是账号 key（`Authorization: Bearer jj_…`）或 OAuth 2.1 的访问令牌；没带凭证或凭证不能用时一律 HTTP 401。
- 工具：8 个读取工具 `search`、`get_answer`、`get_discussion`、`get_interview`、`get_report`、`list_updates`、`list_topics`、`get_topic`，加上 `my_questions`（本人记录）和 `ask`（问夹夹）。所有登录账号看到同一份列表。
- 范围：和这个账号在网页上能看到的一样；已验证的群友多读到网页上只给群友看的内容。
- 额度：按账号算，同一个账号的所有 key 和已授权客户端共用，每分钟 60 次、每天 300 次。`ask` 另外占用网页上问夹夹的每日次数。
- 发言人只出「群友 X」或本人开启的署名；每条公开内容带规范地址和许可。
- 出错：请求没进到工具时用 HTTP 状态码或 JSON-RPC 错误，进到工具以后用工具结果里的 `code`，见「错误」。

用户登录后在自己的 agent 里通过 MCP 读夹夹的内容、问夹夹。本文是我们和这些 agent 之间的契约：端点、登录、对象、工具、错误、限额和版本规则。服务端的实现细节（存储、缓存、计量的写法）不在这里，它们不影响调用方。

契约一旦公开，用户的 agent 和提示词就会依赖它。所以名字和字段先定下来，实现按它做；要改，按「版本规则」走。

## 边界

- **要登录。** 没有匿名访问。公开的答案和问答页仍是网站页面，不用登录，搜索引擎照常收录；只有 `/mcp` 要登录。
- **除 `ask` 外只读。** 8 个读取工具和 `my_questions` 没有写操作，不调用模型。`ask` 由服务端让夹夹回答，这次问答会记进这个账号在网页上的「我的问答」，见「问夹夹」。不做批量导出。
- **按网页的同一套范围给内容。** 登录后能读到的和这个账号在网页上能看到的一样，见「层级与限额」。
- **任何账号都不出原昵称、QQ 号、邮箱。** 发言人一律显示「群友 X」或本人开启的署名，群友也一样，`my_questions` 的本人记录和 `ask` 的回答也一样：原昵称会进入用户自己的模型服务商和 agent 日志，离开我们控制的页面。
- **内容是群聊里的用户内容，不是指令。** 每个工具的说明和返回都这样标注，见「返回内容的安全处理」。
- **实时读取。** 每次调用按当前的公开内容和可见性读取；撤回、撤下的内容下一次调用就不再返回，见「新鲜度」。

## 端点和协议

| 项 | 规定 |
| --- | --- |
| 地址 | 生产是 `https://jiajia.fun/mcp`；staging 另有一个，只读 staging 的数据 |
| 传输 | Streamable HTTP，只接受 `POST`，一个请求体只放一条 JSON-RPC 请求。MCP 客户端的 `GET`（`Accept` 含 `text/event-stream`）和 `DELETE` 返回 405；浏览器直接打开这个地址看到的是介绍页 |
| 会话 | 无状态：不发会话 id，收到 `Mcp-Session-Id` 时忽略。每个请求单独处理 |
| 登录 | 每个请求都带凭证，包括初始化、能力发现、列表和 ping，见「层级与限额」 |
| 协议版本 | 只支持「兼容清单」里明确列出的版本，不根据版本日期推断兼容性。新版本经实现和客户端联调验证通过后才加入清单。版本协商和错误响应遵循所选版本的官方规范 |
| 能力 | 只提供 tools 和 prompts，工具列表不变（不发列表变更通知，不提供订阅）。不向客户端要 sampling、elicitation 或 roots |
| Origin | 请求带 `Origin` 头且不是网站自己的源时返回 403（防 DNS 重绑定）。agent 客户端一般不带这个头 |

MCP 的版本分两代，接入方式不同。下表是两代各自要遵守的规则；我们支持哪一代、哪几个版本，以兼容清单为准。

| | 新一代：2026-07-28 起 | 旧一代：2025-11-25 及之前 |
| --- | --- | --- |
| 怎么开始 | 没有握手。每个请求在 `_meta` 里带协议版本、客户端信息和客户端能力；服务端实现 `server/discover`，客户端可以先调它，也可以直接调用工具 | 先发 `initialize` 握手，再发 `notifications/initialized`（返回 202、不带正文），之后才调用工具 |
| 协议版本 | 每个请求都带 `MCP-Protocol-Version` 头，值必须和 `_meta` 里的一致，不一致返回 400 和 `HeaderMismatch`（-32020）。版本不支持时返回 400 和 `UnsupportedProtocolVersionError`（-32022），在 `supported` 里列出我们支持的版本 | 握手时协商；之后的请求带 `MCP-Protocol-Version` 头 |
| 请求头 | 还要带 `Mcp-Method`，调用工具和取 prompt 时带 `Mcp-Name`；和请求体不一致或缺失时返回 400 和 `HeaderMismatch` | 没有这两个头 |
| 客户端信息（计量用） | 每个请求的 `_meta` 里都有 `clientInfo` | 只在 `initialize` 里有。我们不保持会话，后面的 `tools/call` 拿不到它，接入工具类别记为「未知」 |
| 方法不存在 | HTTP 404，JSON-RPC 错误码 -32601 | JSON-RPC 错误码 -32601 |

规则来源：[MCP 版本说明](https://modelcontextprotocol.io/docs/2026-07-28/learn/versioning)、[2026-07-28 版 Streamable HTTP](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http)、[2026-07-28 版版本协商与兼容](https://modelcontextprotocol.io/specification/2026-07-28/basic/versioning)（查询日期：2026-10-24）。引用这些资料不表示本服务已经实现对应版本。

### 兼容清单

经实现和客户端联调确认的协议版本。和 `schema/compat.json` 一致，`npm run check:contract` 检查。

- `2026-07-28`
- `2025-11-25`
- `2025-06-18`

要不要同时支持旧一代，按实际客户端决定：只支持新一代时，还停在旧一代的客户端连不上；同时支持两代时，按请求是否带新一代的 `_meta` 判断走哪一套。

### 决定：兼容清单收联调确认的三个版本，两代都支持

- **日期和来源**：2026-11-02，维护者（Joye-Co/qqbot#1534，联调见 Joye-Co/qqbot#1533）。
- **决定**：清单是 `2026-07-28`、`2025-11-25`、`2025-06-18`，新旧两代都支持。旧一代的请求缺 `MCP-Protocol-Version` 头时按规范当作 `2025-03-26` 处理（有的客户端握手后的通知不带这个头），但 `2025-03-26` 不在清单里：`initialize` 不会协商出它，显式带这个头的请求返回 400 和 -32022。
- **依据**（staging 联调，2026-11-02）：Claude Code 2.1.316 用 `2026-07-28`；Cursor 用 `2025-11-25`；Codex CLI 0.166.0 和 Gemini CLI 0.66.0 用 `2025-06-18`。三个客户端用 key 和 OAuth 都完成了连接、`tools/list` 和工具调用。Claude 网页版、ChatGPT 还没测，测完按结果补充。
- **放弃的方案**：只支持新一代：主流客户端里只有 Claude Code 在用，其余都连不上。把 `2025-03-26` 也加进清单：没有客户端协商它，没测过的版本不进清单。
- **重新评估**：Claude 网页版、ChatGPT 实测之后；新的协议版本发布时。

### 决定：无状态，不保持会话

- **日期和来源**：2026-10-24，维护者。
- **决定**：服务不保持会话，不发 `Mcp-Session-Id`；每次请求都独立核对当前身份和权限。
- **理由**：所有工具都只读，服务器不需要主动推送。新一代协议本身就没有会话；旧一代允许会话但不强制。为旧一代保持会话要在服务端另存状态，换来的只是多一层要维护的东西。代价是旧一代客户端的接入工具类别记不到。
- **放弃的方案**：服务端保存会话。
- **重新评估**：需要服务器主动通知客户端（比如订阅更新）时。

## 对象

每条公开内容结果都是下面四类之一。`type` 区分类型，`id` 在同一类型里唯一且不变。

| `type` | 是什么 | `id` |
| --- | --- | --- |
| `answer` | 答案：从一条或几条讨论里提炼出来的当前最好的回答，审核后发布。旧精华迁成的答案 id 是 `knowledge-<原 id>` | UUID，或 `knowledge-` 开头 |
| `discussion` | 原始讨论：群里的一问一答，或群友的独立讨论 | 问答的短编号（8～23 位十六进制）；也接受 24 位消息 id |
| `interview` | 面经 | UUID |
| `report` | 日报或周报 | 报告 id |

话题（`topic`）不是结果，是浏览答案的目录，`id` 是 slug（小写字母、数字、连字符）。精华不是单独的类型，只以答案的形式出现。

### 公开内容结果的公共字段

| 字段 | 说明 |
| --- | --- |
| `id`、`type` | 见上表 |
| `url` | 网站上的规范地址，带 `utm_source=mcp`。引用时用它 |
| `updatedAt` | 答案按最后更新时间；讨论按回答时间；面经按发布时间；报告按报告日期 |
| `contributors` | 发言人显示名列表，规则见「边界」。摘要不带这个字段，见下面的决定 |
| `license` | `CC BY-NC 4.0` |

答案另有 `asOf`（信息截至日期）和 `mayExpire`（可能过期）。

### 决定：摘要不带 contributors

- **日期和来源**：2026-10-29，维护者（对齐 Joye-Co/qqbot#1186 的实现）。改了上表「每条公开内容结果都有 `contributors`」的原规定。
- **决定**：摘要（`search`、`list_updates` 每组里的条目，`get_topic` 和 `get_answer` 的 `related` 里的答案）不带 `contributors`，用 `get_*` 读全文时才有。其余公共字段摘要照常带。
- **理由**：网站只在读单条答案时才给出贡献者，列表里的答案没有。要给每条摘要都配上，就得每条再读一次，一次搜索变成十几次读取；服务端要求搜索复用网站已有的搜索、不为组装结果逐条补查（Joye-Co/qqbot#1186）。摘要本来只用来判断读哪条。给空数组也不行：会被理解成「没有贡献者」。
- **放弃的方案**：每条摘要补查一次；摘要给空数组。
- **重新评估**：网站的列表接口能直接给出贡献者时。

### 本人记录（`my_questions`）

- 四类内容对象及其公共字段只适用于公开内容。`my_questions` 沿用网页工作台「我的问答」的记录范围和状态，只返回当前账号本人的记录，请求里没有可以指定其他账号或 QQ 的参数。
- 本人记录不附 `CC BY-NC 4.0` 许可，也不生成公开规范地址。
- 所有账号都有自己在网页上的对话（包括通过 `ask` 问的）；已验证的群友另有还没公开的群聊提问和历史 QQ 私聊。这些记录没有经过公开审核和脱敏，返回前同样按「返回内容的安全处理」处理正文，发言人和正文里的称呼同样只出「群友 X」或署名。
- 本人记录关联已公开讨论或答案时，可以附当前仍可见的公开链接。引用前通过对应 `get_*` 工具重新读取，许可以该公开结果为准。撤回公开后不再提供这个链接。

### 问夹夹（`ask`）

- 以当前账号的身份走网页上问夹夹的同一条链路。回答由夹夹的模型生成，不是审核过的内容：`sources` 列出回答里引用的站内页面，引用前打开来源或用对应的 `get_*` 核对原文。
- 和网页共用每日提问次数和对话记录：这次问答会出现在网页「我的问答」和 `my_questions` 里，`remaining` 是今天还能问几次。
- 回答不附 `CC BY-NC 4.0` 许可，也没有规范地址；正文同样按「返回内容的安全处理」处理。

## 工具

8 个读取工具和 `my_questions` 标 `readOnlyHint: true`、`destructiveHint: false`、`idempotentHint: true`、`openWorldHint: false`。`ask` 标 `readOnlyHint: false`、`destructiveHint: false`、`idempotentHint: false`、`openWorldHint: false`：每次调用都生成新的回答，占用一次网页提问次数，并留下一条对话记录。

| 工具 | 参数 | 返回 |
| --- | --- | --- |
| `search` | `query`（必填）、`kind`（`answer` / `discussion` / `interview` / `all`，默认 `all`）、`topic`（可选）、`cursor`（可选） | 按类型分组的摘要，每组各自一个 `nextCursor`，见「续页」。零结果见「错误」 |
| `get_answer` | `id`（必填） | 答案全文：标题、结论、要点、观点对比（有就带）、`asOf`、`mayExpire`、来源讨论的 `url` 列表、相关答案 |
| `get_discussion` | `id`（必填） | 讨论全文：每条消息带 `role`（`bot` 是夹夹，`user` 是群友）、显示名、时间、正文 |
| `get_interview` | `id`（必填） | 面经全文：公司、岗位、轮次和题目、反问、经验 |
| `get_report` | `id`，或 `kind`（`daily` / `weekly`）加可选 `date`（`YYYY-MM-DD`），见「报告查询」 | 报告全文 |
| `list_updates` | `since`、`until`（可选，见「日期规则」）、`kind`（`answer` / `discussion` / `report` / `all`，默认 `all`）、`topic`（可选）、`cursor`（可选） | 这段时间内新增或更新的内容摘要，按类型分组，见「续页」 |
| `list_topics` | 无 | 话题目录：名字、简介、答案数、`url` |
| `get_topic` | `id`（必填） | 一个话题下按步骤排好的答案摘要，没有步骤的答案放最后 |
| `my_questions` | `since`（可选）、`cursor`（可选） | 当前账号在网页工作台「我的问答」中可见的本人记录，见「本人记录」。复用工作台的本人身份与可见性判定，不允许指定其他账号或 QQ；单一列表，见「续页」 |
| `ask` | `question`（必填） | 夹夹的回答（Markdown）、回答里引用的站内来源（标题和 `url`）、今天还能问几次（`remaining`），见「问夹夹」 |

所有登录账号的 `tools/list` 都是这 10 个工具，不按账号类型增减。账号类型只影响读到的范围，见「层级与限额」。

### prompt

- `daily_digest`：无参数。提示对方 agent 读取最近的公开更新和最新日报，结合用户当前任务推荐最多 3 条内容。
- `deep_dive`：只有一个必填参数 `question`，非空字符串。提示对方 agent 检索、阅读并比较相关证据。

两者都只返回提示词模板，服务端不调用模型，也不执行定时任务。

### 参数规则

- `id` 必须是非空字符串。
- `query` 必须是非空字符串，只有空白字符也视为空，返回 `invalid_params`。超过 120 字时服务端先截断再查，不返回参数错误。工具说明里引导用中文关键词、2～4 个词，零结果就换词或改用 `list_topics`。
- `question` 必须是非空字符串，最多 2,000 字；只有空白或超长都返回 `invalid_params`，不截断。
- `search` 和 `list_updates` 不传 `kind` 时，查询该工具支持的全部内容类型；不传 `topic` 时，不按话题筛选。
- 未知参数、类型不对、日期格式不对，都是 `invalid_params`。

### 续页

- `search`、`list_updates` 按内容类型分组，各组独立返回 `nextCursor`；`my_questions` 是单一列表，只有一个 `nextCursor`。其他工具不分页。
- **首次查询**：不传 `cursor` 时，返回所选内容类型各组的第一页。还有后页时 `nextCursor` 为非空字符串，读完为 `null`。
- **续页**：使用同一个工具，保留原查询条件，把目标组的 `nextCursor` 原样作为 `cursor` 传回。服务端只返回该组的下一页及该组新的 `nextCursor`，其他组不出现在本次响应中；这不代表其他组没有结果。
- **游标**：不透明字符串，只能原样传回。它与工具、所属分组和首次查询条件绑定；缺省日期算出的实际范围在本轮续页中保持不变。游标无效或与查询条件不匹配时，返回 `invalid_params`，不静默从头返回。
- **一致性**：每次续页都按当前身份和可见性筛选。不提供跨调用的快照：两次翻页之间内容变了（新发布、撤回），可能出现重复或遗漏。

### 决定：各组各自续页

- **日期和来源**：2026-10-24，维护者。
- **决定**：分组结果的每一组有自己的游标，续页一次只读一组。
- **理由**：让调用方明确选择继续读取哪组结果，无需新增分组参数，也不必重复加载其他组。
- **放弃的方案**：续读一组时重新返回所有组，会重复交付已经读过的内容；另加分组参数，会与游标所属分组重复。
- **重新评估**：需要跨类型统一排序，或需要跨调用保持列表快照一致时，按版本规则重新约定。

### 日期规则

`get_report.date`、`list_updates.since`、`list_updates.until` 和 `my_questions.since` 都使用 `YYYY-MM-DD`，且必须是真实存在的日期。日期按网站的报告时区解释，默认 `Asia/Shanghai`。工具说明写明格式、时区、默认值和范围边界，让调用方的 agent 能根据运行环境提供的当前时间换算日期。

| 情况 | 规则 |
| --- | --- |
| 日期范围 | 包含起止两天 |
| `list_updates` 不传 `since`、`until` | 最近 7 个自然日，含当天，即当天和之前 6 天 |
| `list_updates` 只传 `since` | 从该日到当天 |
| `list_updates` 只传 `until` | 截至该日的 7 个自然日，即该日和之前 6 天 |
| `list_updates` 的开始日期晚于结束日期 | 返回 `invalid_params` |
| `my_questions` 不传 `since` | 沿用工作台范围，不额外限制为最近 7 天 |

### 决定：日期按网站的报告时区

- **日期和来源**：2026-10-23，维护者。
- **决定**：日期参数都按网站的报告时区解释，范围包含起止两天。
- **理由**：统一 agent 和网站对日期的理解，避免跨时区偏移或把「最近 7 天」解释成 8 天。
- **放弃的方案**：按调用方机器的时区解释，或将自然日当作连续 24 小时；两者都可能与网站的日期范围不一致。
- **重新评估**：网站的报告时区或日期筛选规则改变时，同步调整。

### 报告查询

查询参数由用户自己的 agent 根据用户的自然语言请求填写；服务端按参数读取报告，不负责理解相对日期。

- 只传 `id`：按编号读取对应报告。
- 只传 `kind`：读取该类型当前可见的最新一份报告。
- 传 `kind` 和 `date`：读取该类型、指定报告日期的报告。周报取这一期的结束日。
- `id` 与 `kind`、`date` 互斥。同时传入、什么都不传，或只传 `date`，返回 `invalid_params`。这条由服务端检查，不写进 `inputSchema`：部分模型服务商不接受顶层的 `oneOf` / `anyOf` / `allOf`。
- 指定报告不存在或当前不可见时，返回 `not_found`，不自动改为最新报告。

### 决定：8 个工具

- **日期和来源**：2026-10-23，维护者。
- **决定**：公开工具是上表的 8 个；不设精华类型；`search` 和 `list_updates` 带 `topic`；列表翻页用 cursor。
- **理由**：面经只有搜索摘要时，agent 读不到题目和经验；话题 → 步骤 → 答案是结构化程度最高的内容，只有目录、进不去话题，agent 只能退回去搜；精华已经迁成了答案。cursor 用于顺序翻页，不能阻止连续读取全部内容，读取受限流约束。
- **放弃的方案**：`get_discussion` 标出「哪条是纠正」：公开数据里没有这个信息，只能靠模型推断，不可靠。`list_updates` 包含面经：面经没有按日期筛选的读取方式。
- **重新评估**：上线满一周后看各工具的调用次数，有工具几乎没人调用就考虑合并。

### 决定：登录后加 `ask`，`my_questions` 给所有账号

- **日期和来源**：2026-10-29，Tata（Joye-Co/qqbot#1296）。改了 2026-10-23「边界」里「不调用模型，不提供问夹夹」和「`my_questions` 只有群友 key」的原规定。
- **决定**：所有登录账号都有 `ask` 和 `my_questions`，功能不按账号类型区分。`ask` 和网页上问夹夹共用每日次数和对话记录；`my_questions` 所有账号都能看自己在网页上的对话，群友另能看自己在群里的提问和历史 QQ 私聊。
- **理由**：去掉匿名层以后每个调用方都是一个具体账号，问夹夹可以记在这个账号名下，和网页共用同一份次数，MCP 不另开一份模型调用。网页对话本来就属于账号本人，不该只给群友看。
- **放弃的方案**：`ask` 单独给一份 MCP 的提问次数：换个入口就能多问。
- **重新评估**：付费档位上线、需要按档位区分功能时。

## 返回格式

- 字段的精确类型（必填与可选、能否为空、枚举、长度上限）以各工具声明的 `inputSchema` / `outputSchema` 为准（`schema/tools.json`），本文只写语义和规则。每个工具的真实返回都要通过自己 `outputSchema` 的校验。
- 每个工具同时返回 `structuredContent`（配 `outputSchema`）和一份文本 `content`，只读文本的老客户端也能用。
- 成功结果和工具错误结果都符合同一个 `outputSchema`：成功结果带 `contentNotice`，一定没有 `error`；错误结果只有 `error`。文本 `content` 与 `structuredContent` 表达同一个结果。
- `search` 每组每页最多 10 条。
- 摘要只用来判断读哪条；引用前用 `get_*` 读全文。

### 决定：详情工具一次返回全文

- **日期和来源**：2026-10-24，维护者。
- **决定**：`get_answer`、`get_discussion`、`get_interview`、`get_report` 按编号一次返回当前可见、经过安全处理的完整正文，不截断，不用摘要代替，不分段续读。
- **理由**：答案的标题、结论、要点都有字数和条数限制，一次返回不会过大。讨论和报告的实际最大长度还没有量过，分段续读要保证同一版本的正文不漏不重，在没有数据说明需要之前不为它付这份复杂度。以后真要分段，加可选的 `cursor` 参数和 `nextCursor` 字段属于兼容变更。
- **放弃的方案**：所有工具统一按约 8,000 字截断：答案会被截掉。首版就分段续读：见上一条理由。
- **重新评估**：上线前在 staging 数据上测出有讨论或报告超过实际支持的客户端能接收的大小时。

## 错误

错误分两层。请求在进到工具之前就被拒绝的，用 HTTP 状态码或 JSON-RPC 错误返回；进到工具以后出的错，都用工具结果返回：`isError: true`，`structuredContent.error` 里带 `code`，文本 `content` 里给出可读说明。

### HTTP 和协议层

| 情况 | 返回 |
| --- | --- |
| 服务端缺少必要配置 | HTTP 503 |
| `Host` 不是网站的主机名 | HTTP 404 |
| `Origin` 不是网站自己的源 | HTTP 403 |
| `GET`、`DELETE` | HTTP 405 |
| 没带凭证；凭证格式不对、不存在、已过期或已吊销；账号停用或注销 | HTTP 401，见「层级与限额」 |
| 新一代：请求头缺失或和请求体不一致 | HTTP 400，`HeaderMismatch`（-32020） |
| 新一代：协议版本不支持 | HTTP 400，`UnsupportedProtocolVersionError`（-32022），列出我们支持的版本 |
| 方法不存在 | 新一代 HTTP 404 加 JSON-RPC -32601；旧一代 JSON-RPC -32601 |
| JSON 解析失败、批量请求 | JSON-RPC 规范错误 |

这一层由客户端处理，模型一般看不到：请求没有进到工具，不计额度，也不计入用量。

### 工具结果

| `code` | 情况 | 调用方该怎么做 |
| --- | --- | --- |
| `invalid_params` | 参数不对，包括游标无效 | 按说明改参数 |
| `not_found` | 内容不存在、已撤回、已撤下，或对当前调用方不可见；不区分具体原因，不透露这条内容是否存在 | 不要再引用这条；不要重试 |
| `site_closed` | 网站公开内容整体关闭 | 稍后再试，不要换工具绕过 |
| `rate_limited` | 额度用尽；`ask` 的每日提问次数用完，或上一个问题还在回答中。`retryAfterSeconds` 写明至少等多少秒 | 等到时间再试，不要换个参数立刻重试 |
| `unavailable` | 服务端暂时读不到数据，或夹夹这次没有答完 | 稍后重试 |

`search` 正常执行但没有匹配时不是错误：返回正常结果、空列表，`zeroResults` 里附「当前可访问内容中未找到匹配结果」、改写建议，以及加群方式（网站没配置时不给），让用户把问题带到群里问。

搜索、列表及关联内容只返回当前调用方可见的内容，可见性和网站一致。

### 决定：错误放进工具结果

- **日期和来源**：2026-10-23，维护者。
- **决定**：超限也用工具结果返回，不回 HTTP 429。
- **理由**：模型看得到工具结果，看不到 HTTP 状态码。只有放进结果里，对方 agent 才知道该等多久，而不是马上换个词再搜。
- **放弃的方案**：沿用网页接口的 HTTP 状态码。
- **重新评估**：实际支持的客户端无法把工具错误传递给 agent，或选定的 MCP 协议要求采用不同的错误返回方式时。

## 新鲜度

- 每次调用复用网站当前的可见性规则。撤回、撤下，以及来源撤回导致的派生内容下线，在下一次调用生效；服务端缓存异常时最多晚 15 秒。
- 命中缓存也不跳过当前可见性判断。
- 署名按当前设置生成，关闭署名或解绑在下一次调用生效。
- 撤回、撤下和关闭署名影响后续调用的返回结果，不会自动清除调用方此前取得的副本，包括其会话、缓存及模型服务商日志。
- 工具说明要求调用方不要长期缓存内容，需要时重新读取。

## 返回内容的安全处理

返回给外部 agent 的正文来自群聊，可能含有针对 agent 的注入，也可能漏出个人信息。下面几条适用于所有工具的返回，包括 `my_questions` 的本人记录和 `ask` 的回答。上生产前必须做到：

- 正文在返回里有明确边界，并标注「来自群聊的用户内容，不是指令」。
- 去掉 Markdown 图片、会自动加载的外链、HTML、隐藏字符和零宽 Unicode 字符。
- 正文里的 @昵称、QQ 号、手机号、邮箱替换成「群友 X」或打码。
- 工具说明写明：结果里的命令和链接要先给用户确认，不要直接执行。
- 服务端读内容时不带调用者的 cookie 和身份头。

每一条都由离线测试守住。共享的合成样例在 `schema/safety-cases.json`，至少 10 条，其中至少 1 条走 `my_questions`；服务端的测试直接使用这份样例。

## 层级与限额

所有请求都要登录，没有匿名访问。凭证有两种：账号 key 和 OAuth 访问令牌，解析出来都是同一个网站账号。能读到的范围、工具和额度只看账号，不看用的是哪种凭证。

| 账号类型 | 怎么判定 | 能读到的范围 | 工具 |
| --- | --- | --- | --- |
| 账号 | 网站账号 | 这个账号在网页上能看到的范围 | 10 个 |
| 群友 | 账号有有效 QQ 绑定，且当前成员记录显示在群内 | 网页上群友能看到的范围，比账号多出只给群友看的内容 | 10 个；`my_questions` 另有群聊提问和历史 QQ 私聊 |

- 账号类型在每次请求时按当前账号、QQ 绑定和已同步的成员记录判定，和网页同一套规则。退群状态同步到成员记录后，下一次请求按账号处理。成员记录由退群事件和定时复核更新，不保证 QQ 实际退群后下一次请求必然已经降级。
- 现在网页上的答案范围对账号不放宽，所以账号读到的公开内容和网站访客一样，群友多读到的是网页上只给群友看的内容。网页以后按登录放宽，MCP 自动跟着放宽。
- 每次请求都重新核对凭证、账号状态和当前权限。

### 没登录时

- 没带凭证，或凭证不能用（格式不对、不存在、已过期、已吊销，账号停用或注销），返回 HTTP 401。初始化、能力发现、列表和 ping 也一样，不退回任何免登录的范围。
- 响应头 `WWW-Authenticate` 是 Bearer 质询，参数 `resource_metadata` 指向 `https://jiajia.fun/.well-known/oauth-protected-resource/mcp`，`scope` 是 `mcp`；凭证不能用时另加 `error="invalid_token"`。支持 OAuth 的客户端据此发起授权，见下面的「OAuth」。
- 正文是 JSON-RPC 错误，`code` 是 -32001，`message` 写明去网站登录、在「账号设置」里生成 key，或用支持 OAuth 的客户端直接连接；`data.keyUrl` 是登录入口。
- 没登录的请求不计额度，也不计入用量。

### key

- 给能配置请求头的客户端（Cursor、Claude Code 等）：`Authorization: Bearer jj_…`。key 在网站登录后的「账号设置」里生成。
- key 由客户端的连接配置携带，不作为让 LLM 填写的工具参数。
- key 只在生成时显示一次，服务端只存哈希。账号可以随时在网页上吊销，下一次调用就失效。每个账号最多同时有 5 个未吊销的 key。

### OAuth

给只支持 OAuth 的客户端（Claude 网页版、ChatGPT 等）。按 MCP 的授权规范，用 OAuth 2.1：

- **发现**：401 的 `WWW-Authenticate` 指向 `https://jiajia.fun/.well-known/oauth-protected-resource/mcp`（RFC 9728），其中的授权服务器就是网站本身，元数据在 `https://jiajia.fun/.well-known/oauth-authorization-server`（RFC 8414）。
- **客户端身份**：两种方式都支持，都只接受公开客户端（不发、不收客户端密钥）。
  - **Client ID Metadata Document**（[MCP 授权规范 2025-11-25](https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization)「Client ID Metadata Documents」、[draft-ietf-oauth-client-id-metadata-document-00](https://datatracker.ietf.org/doc/html/draft-ietf-oauth-client-id-metadata-document-00)，查询日期：2026-11-02）：授权服务器元数据里 `client_id_metadata_document_supported` 是 `true`。`client_id` 是一个 https 地址，服务端在授权时用 GET 读取它（不带凭证、不跟随重定向、5 秒超时、最大 5 KB），不用先注册。地址的要求：`https`、默认端口、有路径、不带用户信息和片段、主机是公网域名（不收 IP 地址、`localhost`、`.local`、`.internal` 和不带点的主机名）；地址要写成规范形式（主机小写、没有 `.`、`..` 路径段），和文档里的 `client_id` 逐字相同。文档必须是 JSON 对象，`client_id` 和地址逐字相同，`redirect_uris` 1～10 个，每个都是 https 或本机回环地址的 http；`token_endpoint_auth_method` 不写或写 `none`，带 `client_secret` 的文档不收。`client_name` 可选，授权页上标明是客户端自报的名称。文档读不到或不合要求时显示错误页，不跳回客户端。服务端会缓存读到的文档，最长一天后重新读取；读取失败不缓存。
  - **动态客户端注册**：`POST https://jiajia.fun/oauth/register`（RFC 7591）。`token_endpoint_auth_method` 只能是 `none`；`redirect_uris` 1～5 个，必须是 https 或本机回环地址的 http。注册后一天内没有被授权的客户端会被清掉。
- **授权**：`https://jiajia.fun/oauth/authorize`，只接受 `response_type=code` 和 PKCE `S256`；`scope` 只有 `mcp`；带 `resource` 时必须是 `https://jiajia.fun/mcp`；`redirect_uri` 必须和注册时（或元数据文档里）的某一个完全一致，不一致时显示错误页，不跳回客户端。用户在网站登录后看到客户端名称和回调主机（元数据文档的客户端还会看到 `client_id` 的主机），点「允许」才签发授权码。令牌、刷新和吊销用同一个 `client_id`，规则和注册的客户端一样。
- **令牌**：`POST https://jiajia.fun/oauth/token`。授权码 5 分钟内有效，只能用一次。访问令牌 1 小时有效，刷新令牌 30 天有效；每次刷新都换一个新的刷新令牌，旧的立刻作废。令牌以 `jjo_` 开头，放进 `Authorization: Bearer`。
- **吊销**：用户在网页「已授权的应用」里删除授权，或客户端调用 `POST https://jiajia.fun/oauth/revoke`（RFC 7009），这次授权下的所有令牌立刻失效，下一次调用返回 401。
- **不支持**：在浏览器里直接发请求的客户端（`/mcp` 和这些端点都不发 CORS 头）、客户端密钥、`plain` 方式的 PKCE。

staging 的地址各自换成 staging 的主机名。

### 决定：支持 Client ID Metadata Document，保留动态注册

- **日期和来源**：2026-11-02，维护者（Joye-Co/qqbot#1582）。
- **决定**：授权服务器同时支持 Client ID Metadata Document 和动态客户端注册。元数据文档只从公网 https 域名读取，不跟随重定向，限时、限大小，最长缓存一天。
- **理由**：Claude 网页版添加自定义连接器时默认用「公开身份」，也就是 Client ID Metadata Document（Claude 帮助中心「Get started with custom connectors using remote MCP」，查询日期：2026-11-02）；只支持动态注册时，用默认选项会连不上。MCP 授权规范 2025-11-25 把它列为 SHOULD，动态注册降为 MAY。服务端按客户端给的地址发请求，所以只读公网域名、不跟随重定向，免得被用来访问内网或本机的地址（规范「Authorization Server Abuse Protection」）。
- **放弃的方案**：只保留动态注册，在接入说明里提醒改选「自动注册」：很多人会直接用默认项。只接受名单里的域名：对公开服务没有必要，名单要随客户端变化维护。
- **重新评估**：规范的这部分正式发布或有不兼容的修改时；有客户端的元数据文档超过 5 KB 或回调地址超过 10 个时。

### 额度

- 额度按账号算：同一个账号的所有 key 和所有已授权的客户端共用一份，多生成 key 或多连几个客户端不会多拿额度。
- 现在所有账号同一档：`tools/call` 每分钟 60 次、每天 300 次。以后有付费档位时按档位给日额度，工具和读取范围不按档位区分。
- `ask` 除了计 1 次 MCP 额度，还占用网页上问夹夹的每日提问次数。提问次数按网站的报告时区每天重置，用完时 `retryAfterSeconds` 是到下一天的秒数。
- 日额度按 UTC 自然日计算，每天 UTC 00:00（北京时间 08:00）重置。分钟额度按 UTC 整分钟的固定窗口计，窗口内精确计数，并发请求也不会超过；跨分钟边界时短时间内可能先后用到两个窗口的次数。
- 任一额度用尽时返回 `rate_limited`；等待秒数覆盖实际需要等待的时间，同时受多个额度限制时，以恢复最晚的一项为准。
- 服务已受理的每次 `tools/call` 计 1 次，返回内容、零结果或工具错误都计入。没登录、因限流被拒绝的请求，不消耗日额度。初始化、能力发现、工具列表、提示词列表不计次数。

### 决定：每分钟 60 次

- **日期和来源**：2026-11-02，维护者（Joye-Co/qqbot#1537）。替换了 2026-10-29 起的每分钟 20 次，每天 300 次不变。
- **决定**：`tools/call` 每个账号每分钟 60 次。
- **理由**：联调里脚本化的典型任务一分钟 4～13 次，遍历式任务 17～18 次，一次并行扇出一秒内 13 次（Joye-Co/qqbot#1533）。每分钟 20 次时，模型稍有重试就会撞线，而日额度 300 次已经限住了总量。
- **放弃的方案**：保持 20 次：并行扇出加两次重试就到线。
- **重新评估**：上线一周后看实际用量（Joye-Co/qqbot#1543）。

### 凭证失效规则

| 情况 | 处理 |
| --- | --- |
| 用户吊销 key，或删除一个已授权的应用 | 这个 key 或这次授权下的令牌永久失效 |
| OAuth 访问令牌过期 | 客户端用刷新令牌换新的；刷新令牌过期后要重新授权 |
| 账号被停用 | 停用期间所有凭证都不能用；账号恢复后，未吊销的凭证按当前权限继续使用 |
| 账号注销 | 所有 key 和授权永久失效 |
| 主动解绑 QQ | 吊销现有的 key 和授权；之后可以重新生成 key、重新授权 |
| 退出 QQ 群，且退群状态已同步 | 保留凭证，下一次请求按账号处理，读不到只给群友的内容，`my_questions` 不再有群聊提问和私聊 |

解绑时吊销现有凭证，是为了避免旧凭证在账号换绑另一个 QQ 后，自动读到新绑定身份的本人记录。

### 决定：所有请求都要登录，没有匿名层

- **日期和来源**：2026-10-29，Tata（Joye-Co/qqbot#1296、Joye-Co/qqbot#1297）。替换了 2026-10-23 的「匿名层：访客范围，每个 IP 每分钟 20 次、每天 300 次」。
- **决定**：`/mcp` 的所有请求都要登录，没带凭证返回 401。公开的答案和问答页照旧是网站页面，搜索引擎照常收录。
- **理由**：匿名层的额度只能按 IP 算，换 IP 就能继续取内容；按账号算才能对应以后的付费档位。
- **放弃的方案**：保留匿名层，带 key 只是提高限额。
- **重新评估**：付费档位上线时，或者实际支持的客户端里有很多完成不了登录时。

### 决定：凭证无效时返回 401，不退回免登录的范围

- **日期和来源**：2026-10-24，维护者；2026-10-29 去掉匿名层后改写，规则不变。
- **决定**：带了凭证但凭证不能用（无效、已过期、已吊销、账号停用或注销），一律返回 HTTP 401。
- **理由**：凭证在客户端的连接配置里，不经过模型，401 由客户端直接报给用户，用户才会去换 key 或重新授权；支持 OAuth 的客户端收到 401 会自动走刷新或重新授权。吊销凭证的人要的是它立刻不能用。
- **放弃的方案**：凭证失效时按访客范围继续服务：调用方不会察觉，吊销也起不到「停止访问」的作用。
- **重新评估**：实际支持的客户端收到 401 后不能把原因报给用户时。

### 决定：key 和 OAuth 是同一个账号的两种登录方式

- **日期和来源**：2026-10-29，Tata（Joye-Co/qqbot#1296、Joye-Co/qqbot#1297）。替换了 2026-10-23「账号 key 每个 key 每分钟 120 次、每天 5,000 次」的按 key 计额度。
- **决定**：key 和 OAuth 令牌解析成同一个账号；工具、读取范围和额度只看账号，不看凭证类型。额度按账号共用。
- **理由**：两种接入方式拿到的东西一样，以后不会各自长出一套规则；按 key 计额度时多生成 key 就能多拿额度。
- **放弃的方案**：OAuth 令牌带自己的范围或额度；key 和 OAuth 各自计额度。
- **重新评估**：付费档位上线时，或需要按客户端单独限速时。

### 决定：额度所有工具共享，按 UTC 每天重置

- **日期和来源**：2026-10-23，维护者。
- **决定**：额度不按工具分别给；日额度按 UTC 自然日重置；已受理的调用不论结果都计数。
- **理由**：让调用方明确额度适用范围和恢复时间。
- **放弃的方案**：不约定每日起止时间，调用方无法判断何时恢复；按工具分别给额度，会随可用工具数量改变实际总限额；只计有内容的成功调用，无法约束返回空结果或工具错误的调用。
- **重新评估**：调整额度适用范围或每日重置时区时，先更新本文。

## 计量

每天（按 UTC 计）每个「客户端标识 × 接入工具类别 × 账号类型 × 工具」记一行：调用次数、零结果次数和成功返回内容的次数。

- 客户端标识：账号 id 的带密钥哈希，不存账号 id 原文。同一个账号的 key 和 OAuth 记在同一个标识下。
- 不存查询原文、`ask` 的问题和回答、返回正文、具体内容 id 或完整的 User-Agent。`ask` 的对话记录是网页「我的问答」的一部分，不属于计量。
- 要多存东西（例如为知识缺口统计保留零结果的查询词）之前，先改本节、公布隐私口径，再实现。

## 版本规则

- `serverInfo.version` 跟着服务端发版走；本仓库的 npm 包版本跟着 schema 走。
- **兼容变更**：保证原有调用方式仍然有效，已有返回字段的类型和含义不变。在此前提下，可以新增工具、新增可选参数、在返回里新增字段，或给返回里的枚举加值。
- **不兼容变更**：工具改名、删参数、改参数含义、删返回字段、新增必填参数、把可选参数改为必填、收紧允许的取值、改变默认行为，或改变已有返回字段的类型，都属于不兼容变更。这类改动不在原工具上做：新增一个工具，旧工具保留至少 30 天，并在它的说明里写明替代者。
- **预发布版本**（如 `v0.1.0-rc.1`）只给服务端开发和联调用，字段名还可能改，不承诺兼容。兼容规则从第一个正式版本开始适用。正式版本的 tag 写成 `vX.Y.Z`，不带 `-`：带 `-` 的 tag 都按预发布处理。
- 能从 schema 看出来的不兼容变更由 `npm run check:compat` 拦下，它只和上一个正式版本比；默认行为变了但 schema 没变的，靠评审。
- 契约改了，先改本文和 `src/contract/`，再改服务端实现。
